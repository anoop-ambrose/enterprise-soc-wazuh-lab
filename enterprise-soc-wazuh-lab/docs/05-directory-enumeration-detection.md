# 05 — Directory Enumeration Detection

# 1. Overview

This phase demonstrates the detection and investigation of web directory enumeration activity against the Apache web server hosted on the monitored CITADEL endpoint.

The activity was generated from the OCTOPUS Kali Linux attacker machine using Gobuster and Nikto. Apache recorded the resulting HTTP requests in its access logs, while the Wazuh Agent collected the telemetry and forwarded it to the SENTINEL Wazuh server for centralized monitoring and investigation.

The objective was to demonstrate how offensive reconnaissance activity can generate observable web-server telemetry that can be investigated from a SOC environment.

---
# 2. Objective

The primary objectives of this phase were to:

- Perform controlled directory enumeration against the Apache server.
- Identify accessible, restricted, and non-existent web resources.
- Observe the resulting HTTP requests in Apache access logs.
- Verify that Wazuh receives Apache web-server telemetry.
- Investigate a Wazuh event associated with the enumeration activity.
- Correlate the offensive activity with endpoint telemetry.

# 4. Directory Enumeration Activity

Directory enumeration was performed from OCTOPUS against the Apache web server hosted on CITADEL.

The following Gobuster command was used:

### $ gobuster dir -u http://192.168.x.xxx \ -w /usr/share/wordlists/dirb/common.txt

Gobuster tested resources from the supplied wordlist and identified several responses from the web server.

The enumeration results included resources such as:

- .hta
- admin
- .htpasswd
- .htaccess
- backup
- index.html
- server-status
- uploads

The results included HTTP status codes such as:

- 200 — successful response
- 301 — redirect
- 403 — forbidden response

# 6. Apache Access Log Monitoring

The Apache server records incoming HTTP requests in:

### /var/log/apache2/access.log

The log was monitored on CITADEL using:

### $ sudo tail -f /var/log/apache2/access.log

During the enumeration activity, requests generated by the scanning tools were recorded by Apache.

The access-log telemetry provides the connection between the offensive activity performed from OCTOPUS and the events later processed by Wazuh.

# 8. Enumeration-Related Wazuh Event

A Wazuh event associated with the enumeration activity was identified during investigation.

The event contains the following relevant information:

| Field            | Observed Value                |
| ---------------- | ----------------------------- |
| Agent            | CITADEL                       |
| Protocol         | GET                           |
| Source IP        | 192.168.x.xxx                 |
| Requested URL    | `/externalization`            |
| Decoder          | `web-accesslog`               |
| Log Location     | `/var/log/apache2/access.log` |
| Rule Description | Web server 400 error code     |
| Rule ID          | `31101`                       |
| Rule Level       | `5`                           |
| User Agent       | `gobuster/3.8.2`              |

The source IP should be interpreted as the enumeration host only when it corresponds to the OCTOPUS Kali system in the current lab network configuration.

The most important correlation point is the raw Apache log contained within the Wazuh event:

### GET /externalization HTTP/1.1" 404 476 "-" "gobuster/3.8.2"

The gobuster/3.8.2 User-Agent provides direct evidence that the HTTP request was generated by Gobuster.

# 10. Detection Correlation

The investigation demonstrates the following sequence:

1 OCTOPUS initiated directory enumeration using Gobuster.
2 Gobuster generated HTTP GET requests against CITADEL.
3 Apache received and recorded the requests in access.log.
4 The Wazuh Agent collected the Apache log event.
5 SENTINEL processed the event through Wazuh.
6 Wazuh generated a web-server error alert for the corresponding HTTP response.
7 The individual event was investigated using the Wazuh Dashboard.

The presence of the Gobuster User-Agent in the raw log provides an important correlation point between the security-testing activity and the Wazuh event.

# 12. Security Analysis

Directory enumeration can generate a large number of HTTP requests as an attacker or security tester attempts to identify available resources.

Potential indicators within web-server telemetry include:
- High volumes of HTTP requests
- Repeated requests for different paths
- Large numbers of 404 responses
- Multiple 403 responses
- Requests for administrative or sensitive resources
- Automated scanner User-Agents
- Rapid sequential requests

In this lab, the Wazuh event contains the following notable indicator:

### User-Agent: gobuster/3.8.2

# 13. SOC Investigation Workflow

The investigation process used in this phase follows a basic SOC workflow:

## Step 1 — Identify the Event

Locate Apache-related security events in Wazuh.

## Step 2 — Identify the Endpoint

Confirm the affected monitored system:
### CITADEL

## Step 3 — Examine the Source

Review the source IP associated with the HTTP request.

## Step 4 — Examine the Request

Review:
### GET /externalization
and the HTTP response.

## Step 5 — Examine the Raw Log

Review the original Apache access-log entry and User-Agent.

## Step 6 — Correlate with Offensive Activity

Compare the Wazuh timestamp and HTTP request with the Gobuster enumeration activity generated from OCTOPUS.

## Step 7 — Document the Finding

Record the observed activity, affected endpoint, source, requested resource, telemetry source, and Wazuh rule information.

---
# 14. Security Recommendations

In a production environment, repeated directory enumeration should be investigated in conjunction with other telemetry.

Recommended defensive measures include:

- Monitor HTTP request rates and unusual URI patterns.
- Monitor repeated 404 and 403 responses.
- Detect automated scanning User-Agents where appropriate.
- Restrict exposure of administrative resources.
- Remove unnecessary directories and files from web roots.
- Apply appropriate Apache security configuration.
- Deploy web application firewall controls where required.
- Correlate web-server activity with network and endpoint telemetry.
- Investigate repeated reconnaissance from the same source address.

# 16. Phase Outcome

This phase demonstrated the complete monitoring path from controlled web-directory enumeration to centralized SIEM investigation.

Gobuster generated directory-enumeration requests against the Apache server on CITADEL. Apache recorded the resulting HTTP activity, and the Wazuh Agent forwarded the relevant access-log telemetry to SENTINEL.

The Wazuh investigation exposed the affected agent, source address, requested resource, Apache log location, raw HTTP request, User-Agent, and detection rule information.

The phase demonstrates how web-server telemetry can be used by a SOC analyst to correlate reconnaissance activity with monitored endpoint events.
